# คู่มือข้อมูลอ้างอิงและการระบุการ์ด

เอกสารนี้กำหนดแนวทางสำหรับการพัฒนาฐานข้อมูลและการตรวจการ์ด ไม่ใช่ข้ออ้างว่าทุกความสามารถติดตั้งในเว็บแล้ว ตรวจสถานะจริงในโค้ดและรายงานก่อนใช้งาน

## หน่วยข้อมูล

หนึ่ง card identity หมายถึงการ์ดหลักในภาษาและชุดที่ออกจริง มี ID ภายในไม่ซ้ำ รวม normal/holo/reverse ที่ต่างกันเพียง finish เมื่อใช้ rarity พื้นฐานเดียวกัน หาก stamp, edition, artwork หรือการออกทำให้เกิดตัวตนที่แยกได้ ให้เก็บความแตกต่างและความสัมพันธ์ไว้ ไม่อนุมานว่าเป็นรายการเดียวจากชื่อหรือภาพคล้ายกัน

## ช่องข้อมูล

- Identity: ID ภายใน, ภาษาที่พิมพ์, ชื่อเดิม, ชื่ออังกฤษพร้อมที่มา, ประเภทการ์ด, ชุดจริง, เลขเต็มและปีออก
- Set: ชื่อชุดต้นฉบับและอังกฤษ, ซีรีส์, ภูมิภาค, ชุดหลัก/ย่อย, วันออก, รหัสที่พิมพ์, สัญลักษณ์, catalog ID และตัวย่อ แยกชนิดเสมอ
- Printed evidence: HP, ประเภท, stage, illustrator, ท่า, ความสามารถ, weakness, resistance, retreat, regulation mark, stamp และ copyright ตามที่มีจริง
- Classification: rarity ที่แหล่งระบุ, rarity พื้นฐานที่ตรวจแล้ว, รหัสที่ DCR แสดง และ finish ที่ทราบแยกจาก rarity
- Provenance: แหล่งต่อค่า, URL/เวอร์ชัน, วันที่ตรวจ, สถานะ verified/source-only/conflict/not-applicable/unknown และหมายเหตุ
- Reference images: แหล่ง, สิทธิ์ใช้, ภาษา, มุมภาพ, คุณภาพ และจุดแยกการ์ด เก็บภาพส่วนตัวนอก public

ช่องที่ไม่มีตามประเภท เช่น HP ของ Trainer ไม่ใช่ข้อมูลสูญหาย ห้ามแปลงช่องว่างเป็นศูนย์หรือยืนยันว่าไม่มีโดยไม่มีหลักฐาน

## ขั้นตอนจากรูปสู่คำตอบ

1. รับภาพหน้าและระบุ request ID; ให้ผู้ใช้เลือกส่งภาพ Gemini โดยแสดงปลายทางและจัดการภาพตามนโยบายของเว็บ
2. อ่านภาษาที่พิมพ์ ชื่อ เลขเต็ม รหัสหรือสัญลักษณ์ HP illustrator stamp และหลักฐานอื่น แยกสิ่งที่อ่านไม่ได้ออกจากข้อเสนอของโมเดล
3. ค้นผู้เข้าชิงจากภาษา เลข ชื่อและหลักฐานที่มี แยกรหัสพิมพ์กับ catalog ID และตัวย่อ ห้ามใช้ copyright year เป็นปีออก
4. เทียบแต่ละข้อเป็นตรง/ขัดแย้ง/ไม่ทราบ ปฏิเสธการเลือกอัตโนมัติเมื่อหลักฐานสำคัญขัดกันหรือแยกรายการไม่ได้ รวม finish ที่ต่างกันอย่างเดียวเป็นตัวการ์ดหลักตามกติกาข้างต้น
5. เมื่อยืนยันหรือผู้ใช้เลือกอย่างมีหลักฐาน ให้กรอกข้อมูลจากรายการภาษาและชุดต้นฉบับเดียวกัน หากข้อมูลไม่พอแสดงผู้เข้าชิงและสิ่งที่ต้องตรวจ โดยไม่เติมค่าจากคนละใบ
6. เมื่อเปลี่ยนรูปหรือแก้ identity ต้องยกเลิกผลเก่าและ source ID ที่ใช้ไม่ได้ กันคำตอบเก่ามาเขียนทับ และรักษาค่าที่ผู้ใช้แก้พร้อมแจ้งตรวจ
7. บันทึกที่มารายช่องและสถานะการจับคู่ ให้บันทึกได้เมื่อฉลากยังไม่พร้อม แต่แจ้งก่อนพิมพ์เมื่อไม่มี profile ที่ยืนยัน

## ฟอร์มและการแปลง

| ช่อง | แหล่งและกติกา |
|---|---|
| Name | ชื่ออังกฤษจากรายการที่ตรวจแล้ว หรือคำแปลที่ระบุว่าต้องตรวจ |
| Set | ชื่อเต็มของชุดที่ออกจริงในภาษาการ์ด ใช้ชื่ออังกฤษที่ตรวจแล้ว ไม่แทนด้วยชุดอังกฤษที่ภาพคล้าย |
| Year | ปีออกของชุด/การ์ดที่มีหลักฐาน ไม่ใช้ปี copyright แทนโดยอัตโนมัติ |
| Card number | เลขพิมพ์เต็มรวมศูนย์นำหน้าและ suffix เช่น 025/165 หรือ 151/XY-P; คีย์ค้นหาต้องแยกจากค่าที่แสดง |
| Rarity | rarity พื้นฐานที่ตรวจแล้วและแปลงตามกฎ DCR ที่มีหลักฐาน ไม่อนุมานจาก holo หรือรหัส promo |
| Cert | ผู้ใช้กรอกหรือสุ่มเอง |
| Grade / Condition | ผู้ใช้เลือกเอง |

การย่อเลขบนฉลากต้องใช้กฎฉลากที่อนุมัติสำหรับแต่ละรูปแบบ ไม่เปลี่ยนเลขต้นฉบับที่บันทึกโดยอัตโนมัติ

## ตรวจคุณภาพและแหล่ง

รัน `python dcr-tag-70x20/catalog/audit-card-metadata.py` เพื่อดูจำนวนช่องที่ไม่ว่างและกลุ่มชื่อ+เลขซ้ำแยกภาษาและชุด ตัวเลขเป็นความครอบคลุมของ snapshot ไม่ใช่การยืนยันความถูกต้องหรือความครบถ้วนทั่วโลก HP ไม่ได้บังคับทุกประเภท

TCGdex snapshot ที่ใช้อยู่ระบุใน catalog/README.md; ตรวจ license ของข้อมูลและภาพแยกกัน แหล่งทางการสำหรับตรวจตัวอย่าง: https://asia.pokemon-card.com/th/card-search/list/?expansionCodes=MA6 และ https://www.pokemon-card.com/card-search/details.php/card/31163/regu/all การใช้ข้อมูลจากแหล่งอื่นหรือเผยแพร่ภาพต้องตรวจเงื่อนไขก่อน เก็บข้อมูลที่ไม่แน่ใจเป็น unknown หรือ review-required

ตรวจรูปแบบหลักฐานด้วย `python dcr-tag-70x20/catalog/validate-metadata-evidence.py` และทดสอบตัวตรวจด้วย `python dcr-tag-70x20/catalog/test-metadata-evidence.py`

ตัวอย่างหลักฐานแยกตามช่องอยู่ใน [metadata-evidence.json](metadata-evidence.json) เป็นทะเบียนตรวจสอบ ยังไม่เชื่อมเป็นตัวอนุมัติจับคู่อัตโนมัติ

## สถานะปัจจุบัน

ระบบยังไม่เทียบหลักฐานครบทุกช่องและข้อมูล MA6/XY-P ยังไม่ครบ ชื่อ/เลขที่ซ้ำและข้อมูลไม่ครบอาจต้องตรวจมือ รายงานนี้และคู่มือไม่ได้ทำให้ snapshot ทุกใบผ่านการตรวจหรือรับประกันการระบุตัวตนอัตโนมัติ
